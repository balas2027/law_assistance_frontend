# TASK: Convert static HTML references into a component-based React app

## CONTEXT
This project has static HTML mockups (Stitch-generated) inside `src/ui_design references/`.
Your job is to rebuild these as a production React app inside `src/`, using the SAME
visual design (colors, spacing, typography, layout) but as reusable, typed React
components with proper routing and state management. Do NOT copy inline styles as-is —
extract them into Tailwind classes (or the existing CSS setup) while preserving exact
visual output.

## EXECUTION STEPS (do in this exact order)
1. Set up `src/routes/router.tsx` with all routes from the mapping table above,
   using placeholder empty pages first — verify routing works before styling.
2. Build `components/ui/*` primitives first (Button, Input, Badge, Card, Modal,
   Dropdown, ProgressCircle, ProgressBar, Avatar, Tag, Tabs) by extracting the
   repeated visual patterns you see across ALL the HTML files (same button style,
   same card style, same badge pills like "Draft"/"Published" appear in multiple
   files — build ONE component, reuse everywhere).
3. Build `components/layout/*` (AppSidebar, AdminSidebar, Navbar, Footer, Topbar,
   RightPanel) — extract from the repeated sidebar/nav markup across the HTML files.
4. Convert each HTML file into its route page + feature components, one at a time,
   in this order: home.html → Sign_in.html → Sign_up.html →
   ai_chat_interface_empty.html → ai_with_chat.html → nyayaai_academy.html →
   ai_academy_article.html → quiz file → admin_dashboard.html → admin_quiz_maker.html.
   For each file:
   a. Identify distinct visual "blocks" (cards, list items, panels) and create a
      feature component per block under `components/features/<domain>/`.
   b. Wire static content to props/types — do not hardcode data that should come
      from state or API (e.g. lesson lists, quiz options, curriculum table rows).
   c. Delete inline `<style>` blocks and re-implement with Tailwind classes,
      matching spacing/colors/font-sizes as closely as possible to the source.
5. Set up Zustand stores AFTER static UI is working:
   - authStore: user, token, login(), logout(), signup()
   - chatStore: messages, activeChat, sendMessage(), chatHistory
   - academyStore: courses, currentLesson, quizProgress, xp, streak
   - adminStore: curriculum list, draft lesson, quiz builder state
6. Connect components to stores via hooks (`useChat`, `useAuth`, `useQuiz`,
   `useCourseProgress`) — no direct store imports inside leaf UI components,
   only inside page-level or feature container components.
7. Add route guards: `(app)` and `(admin)` routes require `authStore.user` to be
   set — redirect unauthenticated users to `/login`.
8. Once every page renders and routes work, do a visual diff pass against each
   original HTML file to confirm pixel-level design fidelity, then remove the
   `src/ui_design references/` folder.

## CONSTRAINTS
- Every component must be typed (props interface, no `any`).
- No component file should exceed ~150 lines — split further into sub-components
  if a single HTML block is complex (e.g. the quiz builder option editor).
- Reuse `components/ui/*` primitives everywhere — do not redefine a button style
  inline in a feature component.
- Keep state colocated in Zustand stores, not scattered `useState` across pages,
  for anything that needs to persist across route changes (chat messages, quiz
  progress, auth).
- Confirm each step works (`npm run dev`, check the route in browser) before
  moving to the next file in the conversion order.

## DELIVERABLE
A working Vite + React + TypeScript app where every route in the mapping table
renders the equivalent of its source HTML file, built from reusable components,
routed via react-router-dom, and backed by Zustand stores — ready to connect to
the FastAPI backend endpoints already defined in `nyayaai-backend/app/api/v1/endpoints/`.
